# hada-publish

> 2026-10-23 `meta-publish` 에서 이름을 바꿨다. 저장 버킷 이름(`meta-publish`)과 `meta_jobs`·`meta_tokens` 테이블은 그대로 쓴다.

노션에서 카드뉴스를 검수한 뒤 컨텐츠(산출물) DB의 `배포 채널`을 고르고 **`배포` 버튼**을 누르면 인스타그램·스레드에 자동으로 발행하는 시스템이다. 영상(숏폼·롱폼)은 유튜브에도 올린다(숏폼은 Shorts). 블로그처럼 자동 발행하지 않는 채널은 게시물 DB 에 채널을 연결한 기록만 만들고, 사람이 직접 올린 뒤 링크를 붙인다.

## 동작

1. `배포` 버튼이 웹훅을 보낸다. 함수가 `배포 채널`을 읽어 할 일을 정한다(아래 '배포 채널'). 예전 채널별 버튼은 상태를 `⚪ 대기`로 바꾸고 `?channel=` 을 붙여 보낸다
2. 함수가 **즉시 202(접수)로 응답**하고, 실제 발행은 백그라운드에서 이어간다
3. 함수는 웹훅 본문에 실려 온 페이지(`data.id`)를 대상으로 잡는다. 페이지가 없으면 `⚪ 대기`로 남은 행을 조회하는 큐 모드로 넘어간다
4. `형식`을 보고 발행 소스를 정하고(아래 '형식별 발행'), 채널별로 잠금을 건 뒤 그 파일을 Supabase Storage 공개 버킷에 올린다 — 메타는 공개 URL만 받기 때문
5. 해당 채널 상태를 `🔄 작업중` → `✅ 완료`(실패하면 `⚠️ 오류`)로 옮기고, 게시물 DB 에 게시 기록(게시 링크·게시일·게시 상태)을 남긴다. 한 채널이라도 성공하면 산출물 `상태`를 `게시완료`로 바꾼다(선택지: 기획 → 게시대기 → 게시완료, 보류. 블로그처럼 사람이 올리는 채널은 올린 사람이 `게시완료`로 바꾼다)
6. `처리 시작 시각`·`발행 시각`을 남기고, 실패가 없으면 `마지막 오류`를 비운다

노션 버튼 웹훅은 10초 안에 응답이 와야 한다. 발행은 그보다 오래 걸리기 때문에 접수 응답을 먼저 보내고 나머지를 백그라운드로 넘긴다. 그래서 **202는 접수일 뿐이고 성공이 아니다.** 실제 결과는 페이지의 `인스타그램 상태`·`스레드 상태`·`유튜브 상태`·`처리 시작 시각`·`마지막 오류`로 확인한다.

채널마다 작업이 분리되어 있어서 인스타그램과 스레드가 서로의 실패에 영향을 주지 않는다. 한 채널이 실패해도 다른 채널은 그대로 올라간다.

스레드 토큰은 60일짜리라 `meta_tokens` 표에 담아두고, 발행할 때마다 마지막 갱신 후 30일이 지났으면 먼저 자동으로 연장한다.

## 형식별 발행

발행 소스는 컨텐츠 페이지의 `형식` 선택값이 정한다. 형식이 비어 있거나 목록에 없는 값이면 발행하지 않고 실패로 기록한다.

| `형식` | 발행 소스 | 인스타그램 | 스레드 |
| --- | --- | --- | --- |
| `카드뉴스` | `컷(프롬프트)`의 각 컷 `미리보기` 이미지 (컷 순서대로) | 캐러셀 2~10장 | 캐러셀 2~20장 |
| `이미지` | 컨텐츠 `미리보기` 첫 이미지 | 단일 이미지 | 단일 이미지 |
| `숏폼(9:16)` · `롱폼(16:9)` | 컨텐츠 `미리보기` 첫 영상(mp4) | 릴스 | 영상 |
| `짧은글` | 파일 없음 | 발행 불가(실패로 기록) | 글만 |
| `긴글` | — | 자동 발행 안 함(실패로 기록) | 자동 발행 안 함 |

예전 이름 `영상-세로(9:16)`·`영상-가로(16:9)`·`카피` 도 그대로 받는다. `긴글` 은 블로그용이라 `배포 채널`에는 블로그만 고른다.

영상은 메타가 처리할 때까지 기다려야 발행할 수 있다. 그래서 컨테이너 상태를 주기적으로 확인한다. 처리 시간이 길어 함수 한도(150초)에 걸리면 그 채널만 실패로 기록되는데, 그때는 `media_publish` 를 부르지 않았으므로 같은 버튼을 다시 눌러도 같은 글이 두 번 올라가지 않는다.

인스타그램은 미디어 없는 발행을 지원하지 않는다. 그래서 `짧은글` 은 스레드 전용이고, `짧은글` 에 `배포 채널` 인스타그램을 고르면 그 채널만 실패로 남고 스레드는 정상 발행된다.

## 컨텐츠 DB 속성

| 속성 | 종류 | 쓰는 주체 |
| --- | --- | --- |
| `형식` | 선택 | 사람. 발행 소스를 정한다(위 '형식별 발행') |
| `컷(프롬프트)` | 관계 | 사람. 카드뉴스일 때 컷 순서대로 이미지를 모은다 |
| `미리보기` | 파일 | 사람. 이미지·영상·짧은글 형식의 발행 소스 |
| `배포 채널` | 다중 선택 | 사람. 인스타그램·스레드·블로그·유튜브. 옵션 이름은 채널 DB 페이지 이름과 같아야 한다 |
| `인스타그램 상태` · `스레드 상태` | 선택 | 버튼이 `⚪ 대기`, 함수가 `🔄 작업중` → `✅ 완료`/`⚠️ 오류`. 비어 있으면 요청 없음 |
| `유튜브 상태` | 선택 | 함수만 쓴다. 업로드 시작에 `🔄 작업중`, 끝나면 `✅ 완료`/`⚠️ 오류`. 요청은 `배포 채널`로만 받고 `⚪ 대기`는 쓰지 않는다. 중복 업로드는 게시물 기록의 게시 링크로 막는다 |
| `실시간 처리 상태` | 수식 | 채널 상태를 모아 작업중·오류일 때만 메시지를 띄운다. 평소엔 빈 값 |
| `마지막 오류` | 텍스트 | 함수. 실패 사유를 남기고 성공하면 비운다 |
| `처리 시작 시각` | 날짜 | 함수. 상태가 `🔄 작업중`으로 바뀐 시점. 워치독이 이 값으로 멈춘 작업을 회수한다 |
| `발행 시각` | 날짜 | 함수. 한 채널이라도 성공하면 기록 |

채널 상태가 요청 표시와 진행 표시를 겸한다. 그래서 별도의 작업중 체크박스도, 전체 요약 `발행 상태` 도 쓰지 않는다. `발행 채널`·`결과` 속성도 삭제했다. 전체 요약은 `실시간 처리 상태` 수식이 채널 상태로 계산한다.

`IG_ACCESS_TOKEN` 에는 만료가 없는 **페이지 토큰**을 넣는다. 그래프 API 탐색기에서 단기 사용자 토큰 → 장기 사용자 토큰(60일) → 그 토큰으로 페이지 토큰 순서로 받고, **토큰 문자열만** 복사해 저장한다. 응답 JSON 을 통째로 붙여넣으면 값 뒤에 `","instagram_business_account":{...}` 같은 조각이 따라붙어 메타가 `401 Malformed access token` 으로 거절한다. 함수가 그런 조각을 잘라내긴 하지만, 값 자체는 깨끗하게 넣는 것이 맞다.

### 4. 표 두 개

Supabase 대시보드 → SQL Editor 에서 아래 파일 내용을 붙여넣고 실행한다. service role 만 읽고 쓸 수 있다.

- `supabase/meta_tokens.sql` — 스레드 60일 토큰 보관
- `supabase/meta_jobs.sql` — 발행 잠금. 같은 행의 같은 채널을 두 실행이 동시에 처리해 같은 글이 두 번 올라가는 것을 막는다. 표가 없어도 함수는 잠금 없이 동작한다

### 5. 스레드 인증 (한 번만, 그리고 60일마다 한 번씩)

Threads API 는 페이스북 로그인으로 붙는 경로가 없어 스레드 자체 OAuth 를 한 번 거쳐야 한다.

1. 메타 앱 대시보드 → 이용 사례 → Threads API 액세스 → 설정 에서 **리디렉션 콜백 URL** 을 등록한다.
   `https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish`
   입력 후 반드시 **Enter** 를 눌러 태그로 만들어야 저장된다.
2. 같은 화면에서 앱 역할에 `ha.da_2025` 를 Threads 테스터로 추가한다.
3. 브라우저에서 아래 주소를 열면 승인 링크가 나온다. 링크를 눌러 승인한다.

   ```
   https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?threads_auth=1
   ```

4. 승인하면 함수로 되돌아오고, 함수가 code 를 60일 토큰으로 바꿔 `meta_tokens` 표에 저장한 뒤 `스레드 인증 완료` 안내를 보여준다.

이후에는 발행할 때마다 토큰이 자동으로 연장된다. 60일 넘게 발행을 쉬어 토큰이 만료되면 3번을 다시 하면 된다.

### 6. 유튜브 연결 (한 번만)

유튜브는 구글 OAuth 로 한 번 승인해 두면 계속 쓴다. 승인 정보(refresh token)는 `meta_tokens` 표에 `youtube` 로 저장된다.

1. [구글 클라우드 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만들고 **YouTube Data API v3** 를 사용 설정한다.
2. OAuth 동의 화면(Google Auth Platform)을 만든다. 사용자 유형 **외부**, 범위에 `youtube.upload`·`youtube.readonly` 를 넣는다.
   브랜딩 페이지에는 앱 이름·지원 이메일·개발자 연락처와 함께 아래 두 주소를 넣는다(승인된 도메인은 `<프로젝트 ref>.supabase.co`). 함수가 직접 보여주는 앱 소개·개인정보처리방침 페이지다.
   - 홈페이지: `https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?page=home`
   - 개인정보처리방침: `https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?page=privacy`
3. **게시 상태를 '프로덕션'으로 바꾼다.** '테스트' 상태로 두면 승인이 7일마다 만료된다. 검수(인증)를 받지 않아도 본인 계정은 '확인되지 않은 앱' 경고에서 **고급 → 이동** 을 눌러 승인할 수 있다.
4. 사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 유형 **웹 애플리케이션**. 승인된 리디렉션 URI 에 아래 주소를 넣는다.
   `https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish`
5. 받은 클라이언트 ID·보안 비밀번호를 Supabase 함수 환경값 `YOUTUBE_CLIENT_ID`·`YOUTUBE_CLIENT_SECRET` 에 넣는다.
6. 브라우저에서 아래 주소를 열면 승인 링크가 나온다. 영상을 올릴 채널의 계정으로 승인하면 `유튜브 인증 완료` 와 채널 이름이 보인다.

   ```
   https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?youtube_auth=1
   ```

**공개 범위 제한.** 2020년 7월 이후 만든 구글 클라우드 프로젝트는 [유튜브 API 감사](https://support.google.com/youtube/contact/yt_api_form)를 통과하기 전까지 API 로 올린 영상이 **비공개로 잠긴다.** 감사 전에는 유튜브 스튜디오에서 공개로 바꾸거나 감사를 신청한다. 요청한 공개 범위와 다르게 올라가면 함수가 컨텐츠 페이지에 `배포 안내` 코멘트를 남긴다.

**하루 업로드 한도.** API 기본 할당량(하루 10,000 단위)에서 업로드 한 번이 큰 몫을 쓴다. 하루 몇 건 수준이면 충분하다. 넘으면 `quotaExceeded` 로 실패하고 다음 날(태평양 시간 자정) 풀린다.

### 7. 노션 `배포` 버튼

컨텐츠(산출물) DB → 속성에서 버튼 하나를 만든다.

- 액션: 웹훅 전송
  - URL: `https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish` (`?channel=` 을 붙이지 않는다)
  - 헤더: `x-admin-key: <ADMIN_SECRET 값>`
  - 본문: 속성 선택은 아무거나 (예: `이름`). 함수는 속성 값을 쓰지 않고 본문에 실려 온 페이지 ID 를 쓴다

상태를 바꾸는 액션은 넣지 않는다. 함수가 `배포 채널`을 읽어 직접 처리한다.

**배포 채널별 동작**

| 채널 | 동작 |
| --- | --- |
| `인스타그램` · `스레드` | 자동 발행. 상태가 이미 `✅ 완료`면 건너뛴다. 그래서 실패한 채널만 다시 하려면 같은 버튼을 다시 누르면 된다. 성공하면 게시물 DB 에 기록을 남긴다(같은 산출물·채널 기록 중 게시 링크가 빈 것이 있으면 그것을 채우고, 없으면 새로 만든다). 성과 트래킹은 이 게시물 기록에 붙인다. 기록에 실패해도 발행은 성공으로 두고 코멘트로 알린다 |
| `유튜브` | 형식이 `숏폼(9:16)`·`롱폼(16:9)` 이고 유튜브가 연결돼 있으면 `미리보기` 첫 영상을 업로드한다. 숏폼은 Shorts 로 올라가고 설명 끝에 `#Shorts` 가 붙는다. 제목은 `유튜브 제목` 속성(텍스트, 없어도 됨)이 있으면 그것을, 없으면 페이지 이름을 쓴다(100자). 설명은 발행 문구(캡션 + 고정 멘트)다. 상태 칸이 없으므로 게시물 DB 의 유튜브 기록에 게시 링크가 있으면 이미 올린 것으로 보고 건너뛴다. 다시 올리려면 그 기록의 게시 링크를 비운다. 영상이 아니거나 연결 전이면 아래 '그 밖의 채널'처럼 기록만 만든다 |
| 그 밖의 채널 (`블로그` 등) | 게시물 DB 에 `이름 · 채널` 기록을 만들고 `채널`·`산출물` 관계를 연결한다. 같은 산출물·채널 기록이 이미 있으면 새로 만들지 않는다. 만든 기록 링크는 컨텐츠 페이지 코멘트로 남는다 |

노션 통합(`NOTION_TOKEN`)이 게시물 DB 와 채널 DB 에도 연결되어 있어야 기록을 만들 수 있다. 연결이 없으면 코멘트에 `게시물 기록 … 실패` 가 남는다.

예전 `인스타그램 배포`·`스레드 배포` 버튼(상태를 `⚪ 대기`로 바꾸고 `?channel=instagram|threads` 로 보내는 방식)도 그대로 동작한다. `?channel=` 이 있으면 그 채널만 처리하고 `배포 채널`은 읽지 않는다.

노션 자동화 웹훅은 실행된 페이지를 통째로 실어 보낸다(`data` 안의 페이지 ID 와 속성). 그래서 버튼 Content 에 페이지 URL 을 넣지 않아도 되고, 어느 페이지를 대상으로 잡았는지 함수 로그의 `hada-publish 대상` 줄에서 확인할 수 있다. 페이지가 실려 오지 않으면 `⚪ 대기`로 남은 행을 줍는 큐 모드로 넘어간다.

## 성과 수집

게시물 DB 에서 `게시 링크`가 있고 `게시 상태`가 `내림`이 아닌 기록을 모아, 채널 API 로 지금까지의 누적 지표를 읽는다. 그 값에서 성과 로그 DB 에 이미 쌓인 합(직접 입력한 행 포함)을 빼서 **늘어난 만큼만** 새 행으로 남긴다. 그래서 게시물의 `총 조회수`·`총 좋아요`·`총 댓글`·`총 저장` 롤업이 채널에 보이는 숫자와 같아진다. 늘어난 게 없으면 행을 만들지 않는다.

| 채널 | 읽는 곳 | 채우는 칸 |
| --- | --- | --- |
| 인스타그램 | 미디어 목록 `like_count`·`comments_count` + 인사이트 `views`·`saved`·`shares` | 조회수·좋아요·댓글·저장·공유 |
| 스레드 | 게시물 인사이트 `views`·`likes`·`replies`·`reposts`·`quotes`·`shares` | 조회수·좋아요·댓글(답글)·공유(리포스트+인용+공유) |
| 유튜브 | YouTube Data API `videos.statistics` | 조회수·좋아요·댓글 |

- 채널은 게시 링크 주소로 정하고, 게시물은 링크 속 코드(인스타 `/p/`·`/reel/` 뒤, 스레드 `/post/` 뒤, 유튜브 영상 ID)로 계정 목록과 맞춘다. 계정 최근 게시물 500개 안에서 찾는다.
- **계정에만 있는 게시물**(노션을 거치지 않고 직접 올린 것 등)은 게시물 DB 에 기록을 새로 만든 뒤 함께 수집한다. 이름은 글 첫 줄(해시태그 줄 제외) 40자 + 채널, `게시 상태` = `게시`, 메모에 자동 생성 표시. `METRICS_IMPORT_SINCE`(기본 2026-10-01) 이후 게시물만 가져온다. 인스타그램·스레드는 계정 최근 500개, 유튜브는 채널 업로드 최근 250개 안에서 찾는다. 스레드 리포스트는 제외한다. `게시 상태`를 `내림`으로 둔 기록은 수집하지 않고 다시 만들지도 않는다.
- **산출물 자동 연결.** 산출물이 빈 게시물 기록(새로 가져온 것과 기존 것 모두, `내림` 제외)은 같은 게시물(채널+코드)이 연결된 다른 게시물 기록으로 산출물을 찾아 붙인다. 없으면 산출물을 새로 만든다: 이름 = 글 첫 줄, `유형` 컨텐츠, `상태` 게시완료, `형식` = 미디어 종류로 추정(릴스·영상 → 숏폼(9:16), 캐러셀 → 카드뉴스, 이미지, 스레드 글 → 짧은글, 유튜브는 /shorts/ 링크만 숏폼), `배포 채널` = 그 채널, `캡션` = 게시물 글, `발행 시각`, 인스타·스레드·유튜브는 채널 상태 `✅ 완료`(배포 버튼이 다시 올리지 않게). 링크는 게시물 기록에만 둔다(산출물 DB 의 `인스타그램 링크`·`스레드 링크` 칸은 더 이상 쓰지 않는다). 게시물 메모에 자동 연결·생성 여부를 남기고, `처리 결과`에 `산출물 연결 N건 · 새로 만든 산출물 N건`이 붙는다.
- 새 행: `이름` = `게시물 이름 · 날짜`, `기록일` = 한국 시간 오늘, `수집 방식` = `자동 수집`, `게시물` 연결.
- 인스타그램 인사이트 권한이 없으면 좋아요·댓글만 남긴다. 스레드는 인사이트가 유일한 경로라 `threads_manage_insights` 권한이 필요하다. 이 권한은 2026-10-23 에 승인 범위에 추가했으므로 **그 전에 받은 스레드 토큰은 인증(위 5번)을 한 번 다시 해야 한다.**
- 한 채널이 실패해도 다른 채널은 그대로 기록한다. 실패 내용은 응답의 `channelErrors`·`results` 와 Actions 로그에 남는다.

예약 호출은 Supabase pg_cron 이 매시 5분에 `?metrics=1&scheduled=1` 로 한다(`supabase/metrics_cron.sql` 을 SQL Editor 에서 한 번 실행). 인증은 `x-cron-key` 헤더로 하고, 그 값은 SQL 이 무작위로 만들어 `meta_tokens` 표(`channel = cron`)에만 둔다. 이 키는 예약 성과 수집에만 통한다. GitHub Actions 예약 실행은 늦거나 건너뛰어서 쓰지 않는다. 함수는 채널 DB 의 `자동 수집 시각`(한국 시간 0~23, 비우면 자동 수집 안 함)이 지났고 오늘 아직 `마지막 수집`이 없는 채널만 돌린다. 한 번에 갱신할 게시물은 채널 DB 의 `갱신 기간(일)`(게시일이 며칠 안인 것만)과 `갱신 개수`(게시일 최신순 N개만)로 줄인다. 비우면 제한 없음이고 버튼 수집에도 같이 적용된다. 새 게시물 가져오기는 이와 별개로 `METRICS_IMPORT_SINCE` 를 따른다. `?wait=1` 이 없으면 접수(202)만 돌려주고 뒤에서 수집하므로 노션 버튼으로도 부를 수 있다(웹훅 URL `…/hada-publish?metrics=1`, 헤더 `x-admin-key`). 채널 DB 버튼은 먼저 `수집 상태`를 `⚪ 대기`로 바꾸고 웹훅을 보낸다. 함수가 그 페이지의 `수집 상태`를 `🔄 작업중` → `✅ 완료`/`⚠️ 오류`로 바꾸고 `처리 시작 시각`·`마지막 수집`과 `처리 결과`(시각·확인한 게시물·새 기록 건수·오류)를 남기며, `실시간 처리 상태` 수식이 이를 보여 준다. 결과는 함수 로그의 `성과 수집 결과` 줄과 성과 로그 DB 에서 확인한다. 저장소 시크릿에 `ADMIN_SECRET`(Supabase 함수의 값과 같게)을 넣어야 한다. 손으로 돌리려면 Actions → Collect Post Metrics → Run workflow(`dry_run` 을 켜면 노션에 쓰지 않는다), 또는:

```bash
curl -X POST "https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?metrics=1&wait=1&dryRun=true" \
  -H "x-admin-key: <ADMIN_SECRET 값>" -H "Content-Type: application/json" -d '{}'
```

노션 통합(`NOTION_TOKEN`)이 게시물 DB 와 성과 로그 DB 에 연결되어 있어야 한다.

## 수동 테스트

페이지를 지정하고 `?wait=1` 을 붙이면 접수 응답 대신 실제 결과를 돌려준다. `dryRun` 은 노션 읽기, 컷 정렬, 이미지 업로드, 캡션 조립까지만 하고 발행과 상태 변경은 하지 않는다.

```bash
curl -X POST "https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?wait=1&dryRun=true" \
  -H "x-admin-key: <ADMIN_SECRET 값>" \
  -H "Content-Type: application/json" \
  -d '{"pageUrl":"<컨텐츠 페이지 주소>"}'
```

큐 모드(웹훅이 페이지를 못 실어 왔을 때의 백업 경로)도 `?wait=1` 로 결과를 볼 수 있다. `⚪ 대기`로 남은 행을 전부 처리한다.

```bash
curl -X POST "https://<프로젝트 ref>.supabase.co/functions/v1/hada-publish?wait=1&dryRun=true" \
  -H "x-admin-key: <ADMIN_SECRET 값>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

## 알아둘 제약

- 노션 버튼 웹훅은 10초 안에 응답이 와야 한다. 그래서 함수는 접수(202)만 돌려주고 실제 발행은 백그라운드에서 한다. **202를 성공으로 보면 안 된다.**
- 같은 행의 같은 채널을 두 실행이 동시에 처리하면 글이 두 번 올라간다. `meta_jobs` 표 잠금이 이를 막는다. 표가 없으면 잠금 없이 동작하므로 버튼을 연달아 누르지 않는다.
- 잠금이 15분 넘게 남아 있으면 다음 실행이 가져와 이어서 처리한다. 그래서 함수가 중간에 죽어도 작업이 영영 막히지 않는다.
- 채널 상태가 요청 표시를 겸한다. 함수가 끝까지 못 가면 `🔄 작업중`으로 남고, 그때는 `실시간 처리 상태`가 계속 `작업중`으로 보인다. 원인을 확인하고 상태를 직접 되돌린다. 15분이 지나면 워치독이 `⏱️ 타임아웃 복구`로 바꾸는 것이 2단계 예정이다.
- 한 번의 실행이 함수 실행 시간 한도를 넘지 않도록 110초를 넘기면 남은 행은 처리하지 않고 그대로 둔다. 응답의 `remaining` 에 남은 행이 담기고, 그때는 버튼을 한 번 더 누른다.
- 인스타그램 캐러셀은 2~10장, 스레드는 2~20장이다. 10장을 넘는 카드뉴스는 인스타그램에 올릴 수 없어 지금은 분할하지 않고 실패로 기록한다.
- 인스타그램은 이미지가 공개 URL이어야 한다. 노션 파일 링크는 만료되는 서명 URL이라 발행할 때마다 Storage에 다시 올린다.
- 노션은 업로드된 파일을 `binary/octet-stream` 으로 돌려주기도 한다. 그래서 content-type 을 믿지 않고 파일 앞바이트(이미지는 PNG·JPEG·WebP·GIF, 영상은 `ftyp`·EBML 헤더)로 실제 형식을 판별한다.
- 영상 처리 시간은 이미지보다 훨씬 길다. 컨테이너 대기 시간을 인스타그램 72초, 스레드 40초로 묶어두었다. 이 안에 끝나지 않으면 그 채널은 실패로 기록되고, 다시 누르면 새 컨테이너로 다시 시도한다.
- 인스타그램 릴스는 9:16 세로 영상이 기준이다. `롱폼(16:9)` 도 릴스로 올라가지만 좌우 여백이 생긴다.
- 메타는 거절한 토큰을 오류 문구에 그대로 되돌려준다. 그래서 함수는 API 오류를 요약(`message · code · subcode · trace`)해 기록하고, 알려진 비밀값이 문구에 있으면 `***` 로 가린 뒤 노션에 쓴다. 토큰 값 자체는 로그에도 남기지 않는다.
- 환경값 토큰에 따옴표나 JSON 조각이 섞여 들어오면(`EAA...","instagram_business_account":{...}` 처럼) 함수가 토큰 부분만 잘라 쓰고 로그로 알린다. 토큰 길이가 40자 미만이면 발행을 시작하지 않고 설정을 확인하라는 오류를 남긴다.
- 스레드 캐러셀은 자식 컨테이너가 준비되기 전에 부모를 만들면 `400 (code 100, subcode 4279004)` 로 거절한다. 그래서 자식 전부의 처리가 끝난 뒤 부모를 만들고, 그래도 거절당하면 3초 간격으로 다시 시도한다(최대 6회). 부모도 처리 시간이 필요하므로 발행 전에 상태를 확인한다.
- 컨테이너를 막 만든 직후에는 아직 모든 노드에 보이지 않아 "없다"는 답(`code 24`, `subcode 4279009`)이 올 수 있다. 이 오류는 전파 지연으로 보고 넘긴다.
- 캡션은 선택이다. 비어도 발행하고, 그때는 글 없이 미디어만 올린다(`caption`·`text` 파라미터를 아예 빼고 보낸다). 글이 본체인 `짧은글` 형식만 캡션이 필요하다.
- 캡션은 채널별로 따로 검사한다. 인스타그램 2200자, 스레드 500자다. 두 채널 모두 쓰려면 해시태그 없이 고정 멘트를 포함해 500자 안으로 쓴다.
- 실패한 채널은 `배포` 버튼을 다시 누르면 된다. 성공한 채널은 상태가 `✅ 완료`라 다시 발행되지 않는다. 다시 올리고 싶으면 그 채널 상태를 비운다.
- 날짜 속성은 Notion REST 형식(`{"처리 시작 시각": {"date": {"start": "..."}}}`)으로 쓴다. 이 형식을 틀리면 페이지 속성 PATCH 가 통째로 거부된다.
